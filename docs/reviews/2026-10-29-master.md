## Minor

### 🟡 No non-root USER in Dockerfile, `backend-fastapi/Dockerfile:1`

**Problem**: The image runs as `root` (the default for `python:3.12-slim`). There is no `RUN adduser` / `USER` directive.

**Why it matters**: Running containers as root is a container security best practice violation. If a dependency or app code has a path-traversal or command-injection vulnerability, the process has full root access inside the container. Render's container runtime does provide some isolation, but defense-in-depth means the process should not be root.

**Suggested fix**: Add before the `CMD`:
```dockerfile
RUN addgroup --system appgroup && adduser --system --ingroup appgroup appuser
USER appuser
```

---

### 🟡 `pytest` and `httpx` in production requirements, `backend-fastapi/requirements.txt`

**Problem**: `pytest` and `httpx` are in `requirements.txt` with no separation between production and development dependencies. The Docker image installs every package in that file, so the deployed container carries test tooling.

**Why it matters**: Larger image, longer build time, and a marginally wider attack surface in production. No functional breakage.

**Suggested fix**: Split into `requirements.txt` (prod only: remove `pytest`, `httpx`) and `requirements-dev.txt` (test deps: `pytest`, `httpx`, `anyio`). Add a note in the `Dockerfile` comment that `requirements-dev.txt` is for local dev only. This is a common convention and straightforward to adopt.

---

### 🟡 `EXPOSE 8000` is a static hint but `PORT` is dynamic, `backend-fastapi/Dockerfile:16`

**Problem**: `EXPOSE 8000` documents port 8000 as the exposed port, but Render injects `PORT=10000` (or another value). The app correctly binds to `${PORT:-8000}` at runtime, so traffic routes properly, but the `EXPOSE` line creates misleading documentation (it does not actually open a port; it is a metadata hint only).

**Why it matters**: Low impact on behaviour. Developers who read the Dockerfile to understand the expected port will get 8000 when Render actually sends traffic to 10000+. It is a documentation inconsistency.

**Suggested fix**: Either remove `EXPOSE` entirely (the runtime port is dynamic and documented in `.env.example`) or change it to `EXPOSE ${PORT:-8000}` which is valid Docker syntax and self-documents the dynamic binding.
